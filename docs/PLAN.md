# Mixion — MVP 設計提案（ウェブアプリ版）

作成日: 2026-09-05（Tauri 版から改訂）
対象: 実写動画をフレーム単位で印刷 → 手作業加工 → スキャン → 動画に戻す制作フローの「面倒な部分だけ」を自動化する小さなツール。

---

## 0. 要件の整理

### 確定していること
- 4ステップの一直線フロー: **Print → Draw → Scan → Animate**
- 入力: 動画ファイル（D&D）、FPS（6 / 8 / 12 / 任意）、1ページあたりのフレーム数（2×2 / 3×3 / 4×3）
- 出力: 印刷用PDF（A4）、最終動画（MP4 / GIF）、可能なら元音声を再結合
- スキャン側 v0.1 は「ユーザーが四隅をクリック → パース補正 → グリッド分割」で可
- 完全ローカル処理。外部サーバーへの送信なし
- **ウェブアプリ。サーバー・データベース・アカウントは持たない**（会話で確定）
- 技術: React / TypeScript / Canvas / PDF生成ライブラリ、必要ならOpenCV
- 最初のゴール: 5秒動画 → 8fps → 40フレーム → A4×10枚（2×2）→ 印刷 → 手描き → スキャン → 40フレーム復元 → MP4

### 「ウェブアプリ」の意味
- Vite でビルドした静的ファイルだけで動く。`npm run dev` で手元で開くか、任意の静的ホスティングに置く
- 動画もスキャン画像もブラウザの外に出ない。ネットワーク通信は最初のページ読み込みだけ
- Tauri / Rust / FFmpeg のインストールは不要

### 状態を持たない設計（MVPの方針）
印刷とスキャンの間には数日空くのが普通なので、「何かを保存しておく」設計にすると保存場所の問題が出る。代わりに**紙自体に設定を持たせる**。

- 各ページの QR に、レイアウトを再構築するのに必要な情報をすべて入れる（fps、グリッド、ページ番号、総ページ数、フレーム範囲、総フレーム数、元動画の縦横サイズ、プロジェクトID）
- スキャン側は最初の 1 枚の QR を読むだけで設定を復元する。QR が読めなければ手入力する（項目は 4 つだけ）
- 元動画は Scan 側でもう一度ドロップしてもらう。音声と、未スキャンフレームの代用に使う。ドロップしなければ無音・代用なしで進む
- Print 画面と Scan 画面は完全に独立して動く。リロードすれば消えるが、消えて困るものは紙と元動画に残っている
- ブラウザ内保存（IndexedDB）は「作業途中の四隅クリックをリロードで失いたくない」と感じてから足す

### こちらで置いた解釈・仮定
| 項目 | 仮定 |
|---|---|
| 「切り取り位置ガイド」 | 物理的にハサミで切る線ではなく、「最終動画に入る範囲（クロップ枠）」の目印。ページを切ると四隅マーカーが失われるため、**ページは切らずにスキャン**する |
| スキャン入力形式 | JPEG / PNG（1ページ1ファイル）。PDF はMVPでは非対応 |
| スキャン機材 | フラットベッドスキャナ想定。スマホ撮影もパース補正で吸収できるが、照明ムラは補正しない |
| 用紙 | A4のみ。向きは元動画のアスペクト比とグリッドから自動決定 |
| 出力解像度 | 元動画と同じ解像度（上限 1920px幅）。QR に入れた縦横サイズから決まる |
| 未スキャンのフレーム | エラーにせず、元動画のフレームで代用して警告表示。元動画がなければ直前のフレームを保持 |
| 対応ブラウザ | **まず Chrome / Edge**。WebCodecs と File System Access API が揃っている。Safari は後で確認 |
| 保存 | ブラウザのダウンロード。Chrome 系では保存先を選べる |

### 設計上の最重要ポイント
1. **レイアウト計算を純粋TS関数1つに集約し、PDF生成とスキャン分割が同じmm座標を使う。** ここがズレると全部ズレる。
2. **切り出しは四隅マーカーからの相対座標で行う。** 既知のmm位置とスキャン上の4点のホモグラフィで、印刷時の拡大縮小やスキャン解像度の違いを吸収する。「100%で印刷して」と要求しない。
3. **QR にレイアウトの入力値をすべて入れる。** `computeLayout(QRの中身)` でスキャン側が同じレイアウトを再構築できる。これが「状態を持たない」を成立させる。
4. **v0.2 以降の自動化は「4点の座標がクリック由来かマーカー検出由来か」の差だけ。** 後段のパイプラインは最初から共通。

## 1. MVP 仕様

### 1.1 Print
- 動画ファイルを D&D またはファイル選択で読み込む（mp4 / mov / webm）
- 読み込み時に WebCodecs で取得: 長さ、解像度、音声有無 → 表示
- FPS: `6` `8` `12` のチップ + 任意入力（1〜30 の整数）
- グリッド: `2×2` `3×3` `4×3`（列×行）
- 自動計算して表示: 総フレーム数 = ceil(長さ × fps)、ページ数 = ceil(フレーム数 / 1ページのフレーム数)、用紙の向き
  例: 5.0秒 × 8fps = 40フレーム → 2×2 → 10ページ（A4 横）
- ページプレビュー（Canvas、ページ送り可）。PDF と同じレイアウト関数・同じ描画関数を使う
- 「Create Print PDF」でフレーム抽出 → PDF 生成 → ダウンロード（Chrome 系は保存先を選択）
- フレーム抽出: t = i / fps（i = 0 .. N-1）の各時刻に最も近いフレームを取る。N = ceil(長さ × fps) を正とし、動画末尾で取れなければ最終フレームを複製

### 1.2 印刷ページのフォーマット（A4）
```
┌──────────────────────────────────────────────┐  ← 用紙端
│ ■M0            P03/10  #09–#12  [QR]     M1■ │  ← 外周余白10mm、マーカー10mm角
│                                              │
│   ┌──────────────┐    ┌──────────────┐       │
│   │  frame #09   │    │  frame #10   │       │  ← 画像。四隅に細いクロップ目印
│   └──────────────┘    └──────────────┘       │
│     #09                 #10                  │  ← フレーム番号
│   ┌──────────────┐    ┌──────────────┐       │
│   │  frame #11   │    │  frame #12   │       │
│   └──────────────┘    └──────────────┘       │
│     #11                 #12                  │
│ ■M3                                      M2■ │
└──────────────────────────────────────────────┘
```
| 要素 | 仕様 |
|---|---|
| 外周余白 | 10mm。プリンタの印刷不可領域とスキャナの端欠けを避ける |
| 四隅マーカー | ArUco系マーカー 10mm角 + 白の余白2mm。ID = `page*4 + corner`（0=左上,1=右上,2=右下,3=左下）。1個読めればページと向きが分かる（v0.2 以降で使用。v0.1 では黒い■として見えていればよい） |
| ページ番号 | ヘッダに `P03 / 10` とフレーム範囲 |
| QR | ヘッダ右、16mm。内容は下記 |
| フレーム画像 | セルの最大枠にアスペクト維持でフィット。JPEG 品質 85 |
| クロップ目印 | 画像枠の1.5mm内側にコーナーティック。紙の白が動画に入らないためのブリード |
| フレーム番号 | 各画像の直下に `#09` |
| セル間隔 | 6mm |
| 向き | 横 / 縦のうちセル面積が大きくなる方 |

QR の内容（短い JSON。v が layout アルゴリズムのバージョン）:
```json
{"v":1,"p":"k7Qz","pg":3,"of":10,"f":[9,12],"n":40,"fps":8,"g":"2x2","d":[1920,1080]}
```

参考サイズ（A4横、16:9、layout.ts の実測）: 2×2 → 約123×69mm、3×3 → 約75×42mm、4×3 → 約65×36mm

### 1.3 Draw（説明のみ）
- 四隅の■と QR の上は塗らない・貼らない（塗ってしまっても四隅を手動指定すれば復元できる）
- 画像の外にはみ出して描いてよい。クロップ枠の外は動画に入らない
- 厚みのあるコラージュはフラットベッドで
- スキャン設定: 300dpi、カラー、JPEG か PNG、1ページ1ファイル
- ページを切り離さない

### 1.4 Scan
- 「Import Scans」（複数ファイル選択 / D&D）
- 最初の 1 枚から QR を読んで設定を復元し、画面上部に表示（`8fps · 2×2 · 10 pages · 1920×1080`）。読めなければ設定フォームを出す
- 以降の各スキャンも QR を試み、ページ番号を自動入力。読めなければ取り込み順を初期値にして手動選択
- 別プロジェクトの QR（p が違う）が混ざったら警告
- 「Original video（任意）」のドロップ欄。音声と代用フレーム用
- 左: スキャン一覧。状態は `四隅未指定` / `OK` / `エラー`
- 中央: 四隅指定キャンバス
  - 左上 → 右上 → 右下 → 左下 の順に 4 点クリック（マーカーの中心）
  - 4 点そろった時点でグリッドの予測枠をオーバーレイ表示し、点をドラッグで微調整できる
  - 拡大鏡
- 「Apply」でホモグラフィ計算 → セルごとに切り出し → メモリ上の出力フレームに登録

### 1.5 Animate（Scan 画面の右パネル）
- フレームストリップ: 1〜N のサムネイル。スキャン由来は通常、元動画代用は黄、直前フレーム保持は赤
- プレビュー再生（指定 fps、ループ）
- 「Export MP4」「Export GIF」、音声 ON/OFF（元動画がドロップされていて音声がある場合のみ）
- MP4: WebCodecs の VideoEncoder（H.264）+ MP4 ムクサー。各フレームの表示時間 = 1/fps。音声は元動画のトラックを再エンコードせずコピー
- GIF: 純 JS のエンコーダ、幅 640px（設定可）
- 保存はダウンロード。Chrome 系では `showSaveFilePicker` で保存先を選択

## 2. アーキテクチャ

```
ブラウザ（Chrome / Edge）
┌────────────────────────────────────────────────────────────────┐
│ React + TS (Vite)                                              │
│                                                                │
│  UI: Print / Draw / Scan+Animate     state: zustand（メモリのみ）│
│                                                                │
│  domain/  layout.ts  frameMap.ts  homography.ts  markers.ts     │
│           ← 純粋TS。DOM 非依存。PDF と Scan の共通基盤             │
│                                                                │
│  lib/video/  decode.ts (WebCodecs)   encode.ts (WebCodecs+MP4)  │
│              gif.ts                   [fallback: ffmpeg.wasm]    │
│  lib/pdf/    pdf-lib + qrcode                                   │
│  lib/files/  D&D, download, showSaveFilePicker                  │
│  workers/    warp.worker.ts（逆写像 + バイリニア）               │
└────────────────────────────────────────────────────────────────┘
        ▲ ファイル D&D                    ▼ PDF / MP4 / GIF ダウンロード
   ネットワーク通信なし。サーバー・DB・アカウントなし
```

### 役割分担
- **状態はメモリだけ。** Print と Scan は独立したモードで、共有するのは紙（QR）だけ
- **動画の入出力は WebCodecs。** デコード（フレーム抽出）とエンコード（MP4）をブラウザ標準 API で行う。読み込み・ムクシング・音声トラックのコピーは mediabunny のようなライブラリに任せる（対応範囲は実装時に要確認）
- **ffmpeg.wasm は保険。** WebCodecs で扱えない入力形式や音声コピーがうまくいかない場合のフォールバック。約 30MB の読み込みと COOP/COEP ヘッダが必要なので、使わずに済めば使わない
- **OpenCV は使わない。** 4 点ホモグラフィは 8×8 の連立方程式を自前で解く。ワープは Web Worker で逆写像 + バイリニア（1 セル 1920×1080 で数百 ms）
- **重い処理は Worker。** ワープ、GIF エンコード、（必要なら）デコードもメインスレッドから外す

## 4. データフロー

### Print
```
動画ファイル (File)
 → decode.ts: メタデータ {duration, width, height, hasAudio}
 → UI で fps / grid 選択
 → settings = {fps, grid, dims}  → computeLayout(settings) → Layout (mm)
 → N = ceil(duration*fps), pages = ceil(N/perPage), projectId = ランダム4文字
 → decode.ts: t_i = i/fps の各フレームを Canvas に描画 → JPEG Blob × N（メモリ）
 → pagePainter で各ページを描画（Canvas プレビュー / pdf-lib 出力）
     マーカー4 / ヘッダ / QR{v,p,pg,of,f,n,fps,g,d} / 画像 / クロップ目印 / 番号
 → pages.pdf を Blob 化 → ダウンロード or showSaveFilePicker
 → 状態は破棄してよい
```

### Scan → Animate
```
スキャン画像 (File[])  [+ 元動画 (File, 任意)]
 → 各画像: デコード → jsQR → payload {v,p,pg,...}
     最初に読めた payload から settings を復元 → computeLayout(settings)
     読めない画像はページ番号 = 取り込み順（手動で変更可）
 → (v0.1) ユーザーが 4 隅クリック / (v0.2+) マーカー検出
 → H = solveHomography(layout.markerCenters[mm] → points[px])
 → 各セル c: 出力画像 (dims) の各ピクセル
        → cropRect 内の mm 座標 → H → スキャン px → バイリニア   (Worker)
     → outputFrames[frame(pg,c)] = ImageBitmap / Blob
 → 未割当フレーム: 元動画があれば t_i のフレームを decode.ts で取得、なければ直前を保持
 → encode.ts: フレーム列 (duration 1/fps) + 音声トラック(コピー) → MP4 Blob
    gif.ts:   フレーム列 → GIF Blob
 → ダウンロード or showSaveFilePicker
```

### フレーム ↔ ページ ↔ セル（1-origin）
```
perPage    = cols * rows
page(f)    = floor((f-1) / perPage) + 1
cell(f)    = (f-1) mod perPage           // 左→右、上→下
frame(p,c) = (p-1)*perPage + c + 1
```

## 9. 技術的に難しい部分・リスク

| リスク | 影響 | 対策 |
|---|---|---|
| **WebCodecs のブラウザ差**（Safari の H.264 エンコード対応、Firefox の対応状況） | 特定ブラウザで動かない | MVP は Chrome / Edge を対象と明記。Issue 9 のスパイクで確定。最終手段は ffmpeg.wasm |
| **音声トラックのコピー**（AAC の再エンコードはブラウザで制限がある） | 音声なしになる | 再エンコードせず元のパケットをそのまま MP4 に載せる。ライブラリが対応していなければ ffmpeg.wasm で結合 |
| **時刻指定のフレーム取得の正確さ**（キーフレーム間隔、VFR 動画） | 40 枚のはずが 39 / 41 枚、フレームのズレ | N = ceil(duration × fps) を正として、各 t_i に最も近いフレームを取る。末尾は複製。実機テスト2で確認 |
| **印刷時のスケーリング / スキャン解像度** | 切り出し位置ズレ | マーカー相対座標 + ホモグラフィで吸収 |
| **絵の具・コラージュがマーカーや QR を隠す** | QR が読めない、自動検出不能 | 設定は手入力で代替できる（4 項目）。四隅は手動指定。Draw 画面で注意喚起 |
| **端欠け・印刷不可領域** | マーカー欠け | 10mm 余白。実機テスト1で確定 |
| **メモリ**（A4 300dpi ≒ 2500×3500px、フレーム 40 枚、出力フレーム 40 枚） | タブがクラッシュ | スキャンは 1 枚ずつ処理して元画像を捨てる。フレームは JPEG Blob で保持し、必要時だけ ImageBitmap 化 |
| **リロードで作業が消える** | 四隅指定のやり直し | 状態を持たない設計なので被害は「そのセッションの四隅クリック」だけ。beforeunload で確認。必要なら後から IndexedDB |
| **保存 UX**（Safari はダウンロードのみ、複数ファイルの扱い） | 保存先が分かりにくい | Chrome 系では showSaveFilePicker。出力は PDF / MP4 / GIF の単一ファイルなので許容 |
| **ffmpeg.wasm を使う場合の COOP / COEP ヘッダ** | ホスティングで設定が要る | 使わずに済ませる。使うなら Vite dev と静的ホスティングでヘッダを設定 |
| **紙の白と動画の白、色味の差** | 眠い仕上がり | MVP ではやらない。1.5mm ブリードで紙端の写り込みだけ防ぐ |
| **js-aruco2 の対応辞書と精度（v0.2）** | 自動検出が不安定 | 手動が本線。ダメなら OpenCV.js に切替できる構造 |

### v0.2（2026-09-05 追加）: 四隅マーカーの自動検出
- 方式: jsQR が返す QR の四隅座標から、スキャンの px/mm と回転を求め（相似変換）、レイアウト上のマーカー位置を予測。予測点の周辺だけを Otsu で二値化し、連結成分からマーカーサイズの黒い正方形を選んで外接矩形の中心を取る。ArUco の ID 復号は使っていない（QR がある限り不要）
- 取り込み時に検出 → 4 点そろえば自動で Apply。足りない隅だけユーザーがクリックする。見つかった点はドラッグで修正可能
- 疑似スキャン（200dpi、±2.5 度回転）10 ページで 9 ページが自動、塗りつぶしたマーカーのあるページは 3 点検出 + 手動 1 点。検出誤差は 1.1 px 以下（約 0.14mm）。10 ページの取り込み〜切り出しで約 13 秒
- 未対応: QR も塗りつぶされたページ（設定は手入力、四隅は手動）。v0.3 の自動パース補正は、この検出でホモグラフィが自動になった時点で実質達成
